# Training coverage

This ledger separates migrated computation from public integration. Verification is not run.

## Agreed object contracts

- Public models expose `native_model` and `runtime`. `MaxTextModel(native_model, runtime)` preserves the native object.
- `resolve_runtime_config(public_config)` and the native `MaxTextConfig`/`RLConfig` validators are authored. An initialized runtime exposes resolved native `HyperParameters` through `runtime.config` and the mesh through `runtime.mesh`; integration has not been executed.
- `MaxTextTrainingEngine` receives an optional keyword-only `model=None`. Supplying a native model must bypass model creation.
- Infrastructure owns `setup_train_loop(config, recorder, devices=None, elastic_retry_cache=None, *, model=None, mesh=None, runtime=None, data_iterator=None, eval_data_iterator=None, checkpoint_step=-1)`. It retains the effective config, validates physical mesh compatibility and device ownership, and forwards the selected step to checkpoint restore. Pretraining passes its existing runtime and mesh; earlier prebuilt-model initialization remains outside setup's goodput scope.
- Its result retains the original order `(init_rng, checkpoint_manager, state_mesh_shardings, model, mesh, learning_rate_schedule, data_iterator, data_loader, rampup_manager, eval_data_iterator, state)`.
- Public `data.create_data_iterator(config, mesh, *, train_dataset=None, eval_dataset=None, processing_class=None)` returns the native train and evaluation iterators; integration remains unverified.
- `TrainingArguments` exposes `colocated_python_data_input`, `expansion_factor_real_data`, `generate_padding_batch_train`, `generate_padding_batch_eval`, `use_stream_chunking`, `train_shard_in_read`, and `train_interleave_cycle_length`; `None` retains native configuration. The last three apply to `c4_mlperf` and explicit trainer overrides are rejected for other input paths. SFT and DPO reject explicit colocated or padding settings when their selected input path does not consume them. RL rejects these overrides. Grain and TFDS colocated iterators do not consume padding-batch settings, and HF multimodal SFT does not consume them. Integration remains unverified.
- The HF adapter accepts supplied data and `processing_class` through `make_hf_train_iterator` and its evaluation counterpart. Dataset conversion retains native preprocessing; public post-training rejects a supplied `data_collator`.
- `DataLoader(config, mesh, data_iterator, goodput_recorder)` wraps iteration. Grain checkpoint restore uses the original iterator before loader iteration. No exact Hugging Face source-cursor resume guarantee is established.
- Checkpoint save retains `save_checkpoint(manager, step, state, config=None, data_iterator=None, force=False)`. Restore retains `load_state_if_possible` and its original argument semantics.
- Engine checkpoints use a composite `model_params` item and optional `optimizer_state`; engine restore handles this as full-state resume. Orbax 0.12.8's default layout places the model item at `<checkpoint_dir>/<step>/model_params`. Public model-only loading expects a model-state checkpoint, not the composite step root. Engine metadata does not automatically include `scan_layers`; direct model loading from an engine item is not established.
- Explicitly selected pretraining steps are guarded against an absent manager or missing manager step after snapshot restore is attempted. Ordinary Tunix checkpoint resume does not restore the exact prior RNG or iterator stream. These paths remain unverified by execution.
- Ordinary native `Trainer` and Tunix SFT, DPO, and distillation full-state checkpoints carry per-step graph metadata and prepare a selected same-QAT graph before optimizer restore. Tunix QAT with LoRA requires both `save_only_lora_params=False` and `restore_only_lora_params=False` and rejects `lora_restore_path` and distillation's `learn_to_init_mode`; native elastic, emergency, multi-tier, snapshot and dynamic restore paths have restrictions or unknowns. FP optimizer migration is not supported, and unmarked or stateless checkpoint provenance is unknown. These paths are source-authored, not execution-verified.
- `train_pretraining(config, *, devices=None, resume_from_checkpoint=None)` exposes config-first elastic setup and retry with native configured datasets. Explicit devices remain fixed across resize; supplied in-memory HF datasets are not accepted by this callable. `Trainer(..., model_factory=None)` keeps the supplied native model on the first attempt. On resize, an optional `model_factory(attempt_config, mesh)` must return an equivalent native NNX module on the new mesh; the wrapper then references that module and native setup restores snapshot or checkpoint state. Without a factory, supplied-model resize raises. The factory closure owns construction provenance, including loader-synchronized scan configuration available through `model.construction_config`, and graph transformations such as Qwix LoRA; `attempt_config` is the resolved training configuration, not a guarantee of the loader's effective construction configuration. Factory graph and optimizer state layout must match the saved state. Arbitrary graph mutations are not automatically reproduced. Both paths remain unverified.
- Shared trainer setup overlays the supplied model's actual `construction_config.scan_layers` and enabled LoRA settings onto a copied effective training config; pretraining reapplies this on retry. GRPO's separate config path overlays the actor's actual scan setting for rollout synchronization. Runtime and public config identities remain unchanged. These handoffs are unverified.
- Distillation accepts `train_distill(student_config, teacher_config, is_offline=False, offline_data_dir=None, *, student_model=None, teacher_model=None, mesh=None, train_iterator=None, eval_iterator=None)`. Its configuration-based `build_training_components` does not accept these injected objects.
- Pretraining accepts the setup tuple through `train_loop(config, recorder, state=None, elastic_retry_cache=None, *, setup=None)` and `run(..., *, setup=None)`.
- RL `train` accepts a supplied actor, mesh, datasets, or processed iterators. For pre-model multislice setup, `Runtime.for_rl(config, devices=None)` returns the initialized trainer runtime, resolved sampler config, and sampler devices; construct the model with that runtime and pass the sampler values to `GRPOTrainer`. Existing supplied-model use remains separate. This handoff is authored, not executed.
- RL trainer arguments resolve against the RL schema and preserve the runtime's trainer partition. Native RL derives its step count and does not use the generic gradient-accumulation argument. Default split datasets retain the source train/validation split when only one processed iterator is supplied. Pre-training evaluation syncs the actor held by Tunix, and explicit save directories use Tunix's `actor` checkpoint subdirectory. These paths remain unverified.
- `GRPOTrainer.from_config` partitions devices before model creation, loads the reference first, builds the rollout mesh, and independently loads the actor unless `load_checkpoint_only_once` selects a clone. Loaded wrappers retain their effective construction configs; a clone inherits its reference's config. An explicitly supplied reference remains in use. For a supplied actor without a reference, `train()` independently loads from the actor's construction config when `load_checkpoint_only_once` is false; the true branch retains cloning. This does not reconstruct arbitrary changes to the supplied graph. Rollout integration remains dependent on the inference implementation; this path has not been executed.
- Adapter HF serialization uses `save_adapter_files(output_dir, weights, config, found_modules, model_id)`. Weights must already use the original HF mapping and transposes. Native save/restore uses Tunix's manager API rather than assuming an on-disk item-directory layout.
- HF adapter import converts weights with `convert_lora_to_maxtext_adapter` and applies the resulting tree with `apply_converted_lora_adapter(model, adapter)`. Adapter graph construction, mapping, and native restore use an isolated copy of the model's effective construction config, retained by the PEFT wrapper. The public boundary rejects unmapped, unsupported, duplicate, and unpaired weights and checks model adapter-parameter coverage; the conversion/application path is unverified.

## Dependency evidence

`src/dependencies/extra_deps/post_train_github_deps.txt` pins Tunix to commit `385551df4643ee3ac3205e813a93c2ff217dffa5`, TPU inference to `b67ae5f8f234fd559cf4b376840e7bb9ae6d3275`, and vLLM to `d626108b1841888ec90aced33367149a6bbc7e4b`. Generated requirement lower bounds are not exact version locks. Tunix payload and metric classes remain the external class objects, not local lookalikes.

The TPU post-training overrides pin Qwix to `0.1.8`; the base requirement is `>=0.1.8`. Original `utils/lora_utils.py:32` patches Qwix parameter lookup to return `None` for an `AttributeError` involving `shape`. The migration omits that global monkeypatch under the no-shims constraint. Source research did not establish the shape-less operand, the resulting behavioral impact, or a behavior-preserving MaxText-side structural correction.

The migrated engine retains the original `model` setter semantics. Replacing `engine.model` after optimizer/state creation can leave stale ownership, as in the original source. Supplied-model integration uses constructor injection, not this setter. No unrelated setter behavior change is included.
