## Cross-owner contracts

- Foundation owns all `_backend/configs`, public configuration/runtime, packaging and root resources. Configuration construction stays inert. Native `pyconfig.HyperParameters` and `common.common_types.Config` remain distinct consumers. The native `MaxTextConfig`/`RLConfig` types, derived validator and `resolve_runtime_config(public_config)` bridge have been authored; runtime behavior and parity remain unverified.
- Explicit runtime preserves `utils.max_utils.maybe_initialize_jax_distributed_system(raw_keys)` and the training mesh contract `utils.maxtext_utils.get_mesh_from_config(config, devices)`. MaxEngine constructs its own native inference mesh.
- Models owns native model/layer/kernel implementations. Inference retains native parameter/state layouts and does not introduce a generic Transformers-state replacement.
- The current model wrapper is `MaxTextModel(native_model, runtime)` with the same native object in `native_model` and a read-only `native_module` alias. It has no public parameter/state tree contract. `runtime.public_config` is inert, `runtime.config` resolves to native configuration after initialization, and its mesh is the training mesh. Generation must not guess a `.params` field or substitute that mesh for the native engine mesh.
- Infrastructure owns common/utils/data/conversion/weight inspection and ordinary checkpoint operations. Training owns trainer/teacher-data/DILoCo workflows. Operations wires their actual callables without editing their files.
- General accelerator profiles, TPU post-training, benchmark API and MLPerf profiles must remain distinct. JetStream uses the repository commit pin; vLLM and external evaluation packages require explicit packaging coordination.
